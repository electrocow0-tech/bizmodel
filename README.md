# bizmodel

**Живой стенд:** https://bizmodel.87-199-207-214.sslip.io: параметры и запуск прогона по кнопке, вход по коду.
**Статическая копия:** https://electrocow0-tech.github.io/bizmodel/: те же результаты без запуска.
Кнопка «Пройти демонстрацию» внизу справа проведёт по шагам.

Конвейер, который берёт компании из открытого каталога, отсеивает неподходящие бизнес-модели по критериям собственника, прогоняет прошедшие через двух независимых агентов и собирает сравнимые карточки с рейтингом.

Вопрос, на который отвечает рейтинг: какую модель мы с наибольшей вероятностью за три месяца доведём до теста и первой оплаты.

## Как это устроено

1. **Источник.** 200 действующих компаний из каталога Y Combinator, поровну из восьми отраслей, не из СНГ. Выборка зафиксирована зерном и снимком `data/source/sample.json`.
2. **Дешёвый слой.** Недорогая модель читает описание, отсеивает явные нарушения критериев и грубо оценивает скорость запуска. В глубокую проверку идут 15 лучших, не больше трёх из одной отрасли.
3. **Лес решений.** Пять деревьев, по одному на критерий (`config/criteria.yaml`). Шесть моделей разных семейств отвечают на вопросы узлов по найденным страницам, решение принимается пятью голосами из шести. Спорные вопросы разбирает арбитр, нерешённые уходят человеку. Путь по дереву и исход считает код.
4. **Критик** ищет, почему модель не сработает, и подкрепляет возражения источниками.
5. **Проверяющий** открывает источники трёх самых сильных возражений и сверяет их с текстом страницы. Он получает только текст утверждения и страницу.
6. **Карточка.** Модель выставляет уровни по шкалам, балл считает код по весам из `config/scoring.yaml`.
7. **Советник** читает готовую карточку и говорит, запускать ли, сколько вложить и когда остановиться. На балл он не влияет.

У каждого утверждения есть паспорт: источник со ссылкой и цитатой, дата, метод, уверенность. Цитата засчитывается, только если она дословно найдена на сохранённой странице.

## Запуск

Нужны [uv](https://docs.astral.sh/uv/) и три ключа.

```bash
uv sync
cp .env.example .env      # вписать OPENROUTER_API_KEY, ANTHROPIC_API_KEY, TAVILY_API_KEY
uv run bizmodel run       # прогон целиком, результат в runs/<время>/
uv run bizmodel stand     # собрать стенд в docs/ из последнего прогона
uv run pytest             # тесты, сеть и ключи не нужны
```

Ответы моделей и страницы кешируются в `cache/`, поэтому повторный прогон ничего не стоит и даёт тот же результат. Потолок расхода на провайдера задан в `config/models.yaml`: при превышении прогон останавливается.

Остальные команды:

| Команда | Что делает |
|---|---|
| `bizmodel run --profile dev` | Те же шаги на недорогих моделях |
| `bizmodel run --profile local` | Все роли на своём сервере (llama.cpp, vLLM) |
| `bizmodel drill` | Учебный сбой: основной провайдер выключен, отвечает запасной |
| `bizmodel labels` | Таблица для разметки человеком, без ответов моделей |
| `bizmodel score` | Сравнить разметку человека с решениями леса |
| `uvicorn bizmodel.server:app` | Живой стенд с запуском по кнопке; выкладка на сервер - `deploy/deploy.sh` |

## Что где настраивается

| Файл | Что в нём |
|---|---|
| `config/criteria.yaml` | Критерии отбора в виде деревьев вопросов |
| `config/scoring.yaml` | Шкалы, их уровни и веса, правила уверенности |
| `config/models.yaml` | Провайдеры, модели по ролям, запасные маршруты, бюджеты |
| `config/pipeline.yaml` | Размеры воронки, зерно, допущения о команде и бюджете теста |
| `config/overrides.yaml` | Правки человека: побеждают голоса моделей |
| `config/holding.yaml` | Компании холдинга, чтобы советник видел допродажи |
| `prompts/` | Инструкции для каждой роли |

## Код

Читается сверху вниз от `src/bizmodel/pipeline.py`: в нём шаги идут в том же порядке, что и в списке выше. Каждый шаг в своём модуле (`prescreen`, `gate`, `critic`, `verifier`, `card`, `advisor`), общее для всех - в `llm` (маршруты, кеш, бюджеты), `search` и `validate`.
